# Front hub joint geometry: how the ORIGINAL multibody applies the prescribed steering coordinates (label: hubgeometry)

Scratch and evidence are in `/opt/s12/work_hubgeometry/`:

* Luau probes: `probe1.luau`, `probe2.luau`, `probe3.luau`, `measure.luau`, `travel.luau`, `net.luau`, `rolling.luau`, `camberarg.luau`, `p399.luau`. Their outputs are the matching `*.out` files.
* Closed-form checks: `geom.py`, `attrib.py`.
* Original build in Unicorn: `origcheck.py` / `origcheck.out`, and all 21 car specs after CRT init in `specs.py` / `specs.out`.
* Ghidra exports (project `/opt/nrproj_3`, read-only) are under `gh/`:
  * `ev/`: 005b4060, 005b8c40, 005b2b90, 005b2c40, 005b29c0, 0055e180, 00554e70, 0055d880.
  * `ev2/`: 005b3a90, 005b3c60, 005b3ae0, 0055d9c0, 00554d30, 005b2cd0, 005b2f20.
  * `xref.tsv` and `xref2.tsv` hold the data xrefs. `scan.tsv` holds the operand scan.

`core/` in the work folder is a copy of `/home/user/nrport/core`. Its only change is a tire-argument hook appended to `NR2003CupCore.lua`, used only by `rolling.luau` and `camberarg.luau`. Nothing under `/home/user/nrport` was modified.

Axes are NR2003 vehicle axes: +X forward, +Y left, +Z up. Angles are positive counter-clockwise, so a positive steer angle turns the wheel to the left. Matrices are row-major body→parent, as in 005b8c40. "Chassis frame" means `Wc^T·W`, where the `W` matrices come from the record pointer field `+0x339` (`V.componentPose`).

## Short answers

1. **Hub joint axis.** The steering input is a prescribed revolute coordinate `q` about the hub record's own local **z** axis. Flags `0x300` give prescribed code 6, which is a rotation about axis index 2 (z). The hub frame is the suspension frame rotated by the hub's base Euler angles. In the chassis frame the chain is `R_chassis←hub(q) = A_susp · A_hub · Rz(q)`. Suspension travel does not enter this chain: lfsusp is a pure prismatic joint, flags 4.

   The base angles below are in degrees, as (yaw +0x51, pitch +0x55, roll +0x59). They are written by 0055e9b0 for the Cup default setup:

   | record | yaw | pitch | roll | formula |
   |---|---|---|---|---|
   | lfsusp | 0 | 7.907462 | −1.420269 | pitch = atan(antiDive·h/a), roll = −atan(RC/(track/2)) |
   | lfhub | 0 | −10.407463 | 10.604048 | pitch = −(antiDive pitch) − caster; roll = KPI + RC angle − staticCamber |
   | lfwheel | 0 | 0 | −8.000004 | roll = −KPI |
   | rfsusp | 0 | 7.907462 | +1.420268 | mirror of lfsusp |
   | rfhub | 0 | −10.407463 | −10.604049 | mirror of lfhub |
   | rfwheel | 0 | 0 | +8.000003 | mirror of lfwheel |

   The resulting **steering axis in the chassis frame** is:

   | side | axis vector | caster | inclination (top inboard) |
   |---|---|---|---|
   | LF | (−0.0422879, −0.1600025, 0.9862104) | 2.4553° | 9.2154° |
   | RF | (−0.0422879, +0.1600026, 0.9862104) | 2.4553° | 9.2154° |

   * Caster is measured from vertical, top rearward. The inclination is about KPI 8° plus the static camber of −1.18°.
   * The axis passes through the wheel centre, because the hub and wheel offsets are 0.
   * The Luau core reproduces this to 1e‑6: the measured rotation axis is (−0.042288, ∓0.160002, 0.986210), and the rotation angle equals `q` exactly for |q| ≤ 0.4.
2. **LF/RF symmetry.** For the Cup default setup the geometry is an exact mirror (`δ_LF(q) = −δ_RF(−q)` to 7 digits). Asymmetry can only come from:
   * the separate setup items: caster 0x43/0x44 and camber 0x20/0x21 (through 0x8d/0x8e);
   * the ± term `item 0x9e / spec+0x40` added to 0x8d and subtracted from 0x8e;
   * the RF camber-gain source `[bddde0] < 0`, which selects spec+0x7c. All 21 specs have spec+0x7c = spec+0x80.

   The toe input is symmetric (±c086b0/c086b4, both from item 0x29).
3. **Bump steer.**
   * The multibody has none. The suspension is prismatic along the tilted suspension z axis, and the hub orientation does not depend on travel. Over travel −0.02..0.13 m the measured wheel heading stays at 0.0053912 rad and the camber at −1.19481°.
   * The tire path, generated by 0055d9c0, has an explicit bump-steer term `a = ±spec+0x88 · travel`. That coefficient is **0 in all 21 car specs**.
   * The tire path also applies a camber gain `b = 0.3092114 · travel` (−17.7°/m) about the caster-pitched wheel-attachment x axis. This gives a small *implicit* toe change: toe-out grows by +0.0135 rad/m at q = 0 and by 0.023 rad/m at q = 0.2, on each side.
4. **Ackermann.** There is none. Both hubs get the same `q` (± toe/2), and the mirrored geometry gives a slight **anti**-Ackermann:

   | δ (rad) | (LF − RF) road-wheel angle at the tire (rad) |
   |---|---|
   | 0 | 0.0075969 |
   | 0.2 | 0.0072638 |
   | 0.3 | 0.0068639 |

   Ideal Ackermann for L = 2.794 m and T = 1.5367 m would need about 0.020 rad at 0.2. The constant offset is a static toe-out:

   | contribution, per side | rad |
   |---|---|
   | multibody geometry | 0.00539 |
   | tire-path camber-gain coupling | +0.00063 |
   | input toe (`−c086b0 · 0.9895`) | −0.00222 |
   | **net at the tire** | **0.0037986** |

   The road-wheel angle is `δ ≈ 0.9895·q + toe0`. The slope is 0.9875 at q = +0.4 and 0.9903 at −0.4 for LF, mirrored for RF.
5. **Camber, caster and toe setup items.**
   * **Caster** items 0x43/0x44 (rad) go into the hub pitch: `−antiDive − 57.29578·caster`. They also go into `c082d4/c082d8 = −R_tire·caster` (R = 0.3581686 m). That value is used only as an aligning-moment lever arm in 0054cab0, which feeds force feedback (FFB) and telemetry, not the dynamics.
   * **Camber** items 0x20/0x21 go to 00424860, which computes `0x8d/0x8e = camber + gain·staticDeflection`. 0055e9b0 then puts that into the hub roll, so camber also tilts the steering axis. At run time the tire path adds `gain·travel`. At static ride the tire sees −2.02°, close to the −2.0° setting.
   * **Toe** item 0x29 is used per tick: `lfSteer = δ − c086b0`, `rfSteer = c086b4 + δ`, with `c086b0 = c086b4 = item0x29·0.5`.
   * **Steering rate** is not modelled. The hub velocity cell is never written, and exported states 16 and 22 are always 0.

## 1. Joint structure (verified)

### 1.1 Records and flags (005b29c0 tree, 005b4060 per-record init)

The records sit at `0x727290 + r·0x505`. Values after the build are in `probe1.out`; the original Unicorn build gives the same values in `origcheck.out`.

| r | name | parent | flags | meaning (005b4060 / 005b2c40) |
|---|---|---|---|---|
| 3 | lfsusp | chassis | 0x004 | bit 2: free translation along local **z** (prismatic). State 13/14. |
| 4 | lfhub | lfsusp | 0x300 | `(flags>>7)&7 = 6`: **prescribed rotation, axis 6−4 = 2 (z)**. State 15/16. |
| 5 | lfwheel | lfhub | 0x050 | `(flags>>3)&3 = 2`: free rotation about **y** (spin). Bit 6: axisymmetric. State 17/18. |
| 6/7/8 | rf… | | same | states 19..24 |

005b4060 (`gh/ev/005b4060.c`, asm `005b40b1..005b40e7`) builds the constant base matrix at `+0x1c1` as `005b8c40(+0x1c1, ang51·K, ang55·K, ang59·K)` with `K = [006e97f0] = 0.0174533`. For a prescribed rotation (code − 1 ≥ 3) it takes the else-branch and allocates only the angle `+0x275` and the velocity slot `+0x299 + code·4`. The joint is **not** added to the free-DOF list `+0x7d`, so it is purely kinematic.

005b8c40 (`gh/ev/005b8c40.c`) computes:

`[c2c1, s3s2c1−c3s1, s3s1+c3s2c1; c2s1, c3c1+s3s2s1, c3s2s1−s3c1; −s2, s3c2, c3c2]`

This is `Rz(a)·Ry(b)·Rx(c)`, so +0x51 = yaw, +0x55 = pitch, +0x59 = roll. Each element goes through 0057ca60 (a constant cell).

### 1.2 Binding the input and building the rotation (generated predictor)

* **005b2b90** (`gh/ev/005b2b90.c`) copies the 9 floats `bf6360..` into `*e84474[0..8]` (the loop runs to `0xe84498`). It then runs `005b9d10(e84548)` and `005b9d10(e84498)`, which are the predictor and the solve.
* **005b3c60** (`gh/ev2/005b3c60.c`) handles prescribed codes 4..6. It emits `*(rec+0x35d) = *cursor` and advances `cursor = e84664 += 4`. The cursor is reset to `e84474` at `005b2f5f/005b2f74` (005b2f20) and `005b3096/005b30f5` (005b3090). The tree order gives **lfhub ← e84474[0] → cell ebdd40** and **rfhub ← e84474[1] → ebdd44**.
* **005b3ae0** (`gh/ev2/005b3ae0.c`) handles the rotation. If 005b3c60 returned 1, the axis is `code − 4 = 2`. For a non-axisymmetric record it calls `005b8b50(+0x2d9, 2, +0x35d)`, which builds `Rz(q) = [[c,−s,0],[s,c,0],[0,0,1]]` (`recovery/vehicle_core/005b8b50.c`). It then calls `005b8260(+0x339, +0x309, +0x2d9)`, so world = attach · rel.
  * For the axisymmetric wheel, rel = I (006f74a8) and world = attach, so the wheel spin is not part of the matrix.
* The generated code is translated in `core/NR2003Cup/NR2003CupJIT1.lua:946-1000` (lfhub) and `:1700-` (rfhub):
  * `wfd(8212764 /*ebe11c = lfhub +0x35d*/, rf(8211776 /*ebdd40*/))`
  * then `cos` and `sin` of it
  * then `W_hub[:,0] = cos q·(W_susp·A e_x) + sin q·(W_susp·A e_y)`

  The constant cells `ebf680..ebf6a0` hold the A_hub entries:

  | cell | value | A_hub entry | expression |
  |---|---|---|---|
  | ebf680 | 0.98354793 | A00 | cos b |
  | ebf684 | 0.18064727 | A20 | −sin b |
  | ebf688 | −0.033242851 | A01 | sin b·sin c |
  | ebf68c | 0.98292232 | A11 | cos c |
  | ebf690 | 0.18099324 | A21 | cos b·sin c |
  | ebf694 | −0.17756224 | A02 | sin b·cos c |
  | ebf698 | −0.18402077 | A12 | −sin c |
  | ebf69c | 0.96675116 | A22 | cos b·cos c |

  Here b = −10.407°, c = 10.604°. The original build in Unicorn gives the same values to within 6e‑8 (`origcheck.out`).
* **Steering rate.** 005b2cd0 exports `*(+0x35d)` and `*(+0x381 + code·4)`, which is `+0x399`.
  * `+0x399` points to `ebe0dc` (LF) and `ebe2e4` (RF), and both hold 0 (`p399.luau`).
  * The cells are **read** by the generated solve (`NR2003CupJIT2.lua:3843..3930`, velocity composition, multiplied by attachment constants). No generated or native code writes them; a grep of the JIT, JITG and Core modules finds only reads.
  * Measured: exported states 16 and 22 are 0 for every q, including the tick right after a step in q (`measure.out`). The steer rate therefore adds no angular velocity to the hub or wheel.
* **Suspension.** lfsusp has flags 4 and no rotation. Its relative-rotation pointer `+0x2d9` points to the identity cell `0074fd5c` (`probe2`), and 005b39e0 only updates the translation (`005b3a90` handles prescribed translation codes 1..3, otherwise `+0x2cd += dt·v`). Travel only moves the hub and wheel origin, along `A_susp·e_z`:
  * LF: (0.1375313, 0.0247858, 0.9901873). The wheel moves 0.139 m forward and 0.025 m outboard per metre of jounce (anti-dive geometry).
  * RF: (0.1375313, −0.0247858, 0.9901873).

  Consequently `R_chassis←hub(q) = A_susp · A_hub · Rz(q)` and `R_chassis←wheelAttach = A_susp · A_hub · Rz(q) · A_wheel`.

## 3. Tire path: what the tire actually sees (0055d9c0, `gh/ev2/0055d9c0.c`)

0055d9c0 emits the per-wheel tire callback. The xrefs `0055d9db/9fd/a22/a44` read cells c08520, c08224, c0849c and c085a4. For a front wheel w < 2:

```
a = c08520[w] · susp(+0x2d5)          ; bump steer: travel · (±spec88) = 0 for every spec
b = c08224[w] · susp(+0x2d5) + c0849c[w]   ; camber gain: LF +0.3092114·t, RF −0.3092114·t (+0)
l = (sin a, cos a·cos b, sin b)        ; c08690 = sin a, c08694 = cos a·cos b, c08698 = sin b
axle = W_wheel(+0x309) · l             ; 005b8370 -> c08654   (W_wheel+0x309 = W_hub · A_wheel)
fwd  = normalize(axle × n)             ; 005b7e90 / 005b7fa0 -> c085b0   (n = contact-plane normal c08628)
lat  = normalize(n × fwd)              ; -> c083c8
camber input (0054cab0 param_11) = axle · n   ; c08258 -> p4
param_14 = c085a4[w] · hub(+0x35d) = ∓0.127 · q
```

The generated code matches: see `NR2003CupJIT3.lua` C1 for tire0, lines 37..80.

* For the rear wheels, `a = item0x9c·raxle travel + item0x9b·raxle roll + item0x9d` (track-bar roll and bump steer) and `b = c0849c[w]`. This is outside the scope of this report.
* Measured travel dependence, LF at q = 0 (`travel.out`, travel imposed through the original state import 005b4560):

  |---|---|---|
  | −0.02 | 0.0051221 | −0.841 |
  | 0 | 0.0053916 | −1.195 |
  | 0.0467 | 0.0060212 | −2.022 |
  | 0.13 | 0.0071459 | −3.496 |

  The heading slope is 0.0135 rad/m and the camber slope is −17.70°/m. At q = 0.2 the heading slope is 0.0230 rad/m. Over the whole range the multibody heading stays at 0.0053912 and the multibody camber at −1.19481°.
* Rolling check (`rolling.out`, 0054cab0 argument hook, about 25 m/s):
  * At q = 0, the LF and RF slip angles atan(−p6/p5) are 0.005412 and −0.006007. Their half-difference, 0.00571, matches the tire-path heading of +0.005682 / −0.005717.

## Verified vs inferred

**Verified**, by direct evidence (addresses above, Luau core measurement, and the original Unicorn build):

* The prescribed-rotation semantics: flags 0x300 → code 6 → z axis; the 005b3c60 input binding (lfhub = e84474[0], rfhub = e84474[1]); 005b3ae0/005b8b50/005b8260 composing world = attach·Rz(q); the angle cell equals the input exactly.
* The hub rate cell stays 0, so states 16 and 22 are 0.
* The suspension is pure translation along the tilted z axis.
* All record angles and their 0055e9b0 formulas and constants; the record values are identical in the original build (`origcheck.out`, within 1e‑6°).
* The axis vectors, caster 2.4553° and inclination 9.2154°, from both the measurement and the closed form.
* LF/RF mirror symmetry for the default setup.
* No multibody bump steer.
* The tire-path formula: bump-steer coefficient 0 in every spec; camber gain ±0.3092114; the implicit toe slope.
* The anti-Ackermann numbers and the static toe values.
* The FFB/telemetry-only consumers of c082d4 and spec90.

**Inferred:**

* The physical names of the spec fields: anti-dive, roll-centre height, KPI, camber gain, bump steer, "steer arm". The formulas are verified; the names are not.
* The static deflection `defl[w] = −0.046071 m` in 00424860, back-computed from the item values.
* That the `bf6402..` block written in 005539c0 is a telemetry or replay record.
* That `[bddde0] < 0` is a track-direction or mirror flag.

## Unresolved

* The meaning of `bddde0`. It only changes the RF camber-gain source, and the two values are equal in all specs.
* The physical meaning of `spec+0x90` (0.127 m, applied as ∓0.127·q to the front aligning-moment lever arm). It is FFB only.
* The exact origin of `defl[w]` in the 00424860 loop (the `[ESP+EBX*4+0x3c]` producers at `00424cd9..00424f29` were not traced).
* The Luau image record angles differ from the Unicorn original build by 1 ulp in a few values: lfsusp pitch 7.907462 vs 7.907461, rfsusp roll 1.420268 vs 1.420269, and the attachment constants differ by ≤ 6e‑8. The likely cause is the Stage 10 rebuild's double-precision arithmetic, but this was not traced. The effect is negligible.

## Impact on the Luau port and docs

1. **No physics change is needed.** The core already executes the original hub geometry: the translated JIT callbacks plus the record angles and attachment constants from the build. The Stage 10 garage rebuild recomputes the record angles for other caster and camber values through the lifted 0055e9b0/00424860. Hand-written adapters must not replace this with a "yaw-only" wheel.
2. **Units of the steering coordinate.** `lfSteer/rfSteer` (bf6360/bf6364, states 15/21) are hub joint angles about the inclined steering axis, not road-wheel angles. The road-wheel angle is about `0.9895·q + toe0`, with toe0 = +0.0038 rad for LF and −0.0038 for RF at the tire, including the input toe.
   * Any provisional host contract that hands over a target road-wheel angle should document this.
   * For an exact inverse, use the closed form `A_s·A_h·Rz(q)·A_w`.
   * The cockpit wheel (`car+0x1554 = (s15 + s21)/2`, 005662d0) correctly uses q, not δ.
3. **Do not inject a steering rate.** The original keeps the hub velocity cells at 0, so states 16 and 22 are always 0. A port that differentiates q into the multibody would add steer-rate effects that the original does not have.
4. **Presentation.** `componentPose(5/8)` is the attachment orientation `W_hub·A_wheel`, which is static camber −1.19° and has no spin. The tire uses `W_wheel(+0x309)·(sin a, cos a·cos b, sin b)` with `b = ±0.3092114·travel`. That is −2.02° at static ride, and it adds 0.0135 rad/m of toe. To render what the tire sees, apply the b rotation about the wheel's local x. To render the multibody, use the record pose unchanged.
5. **Docs.** Update `PORT_MAP.md` "Estágio 6":
   * lfsusp angles are (yaw 0, pitch = anti-dive 7.907°, roll = ∓roll-centre 1.420°), in Rz·Ry·Rx order (005b8c40).
   * The hub has a prescribed rotation (code 6) about its local z, with base angles (0, −10.407°, ±10.604°). The wheel roll is ∓8° (KPI removed).
   * The steering axis is caster 2.455°, inclination 9.215°, through the wheel centre.
   * There is no Ackermann and no multibody bump steer.
   * Camber gain and the zero bump-steer coefficient live in the tire callback.
   * The caster trail `c082d4` and the `spec90` term feed only FFB and telemetry.

   In `SETUP_MAP.md`:
   * caster 0x43/0x44: hub pitch, plus FFB trail.
   * camber 0x20/0x21: through 0x8d/0x8e into hub roll, which also sets the steering-axis inclination.
   * toe 0x29: per-tick ±0.5·toe into the hub coordinates.
   * The garage display sign of toe vs the physical toe-in/out is affected by the geometric toe-out described above.
6. **Optional tests:**
   * The axis vector and `δ(q)` table above, as Luau fixtures through `componentPose`.
   * Invariance of the hub pose against travel imposed through 005b4560.
   * States 16 and 22 equal to 0.
